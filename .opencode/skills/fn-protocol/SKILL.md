# Работа с фискальным накопителем (ФН)

Скилл описывает протокол обмена ККТ ↔ ФН по официальному документу ФНС
«Описание протокола информационного обмена между контрольно-кассовой техникой и
фискальным накопителем», **версия 1.2.05 от 09.06.2021** (далее — Протокол), и
то, как этот протокол реализован в `lib/fn` данного репозитория.

Документ охватывает ФН-1 (ФФД 1.0/1.05) и ФН-1.2 (ФФД 1.1/1.2), включая
команды маркировки. Команда сброса МГМ (`60h`) в Протоколе **отсутствует** —
это расширение для тестовых накопителей, см. `references/repo-integration.md`.

## Жёсткие инварианты протокола

Нарушение любого из них — ошибка обмена, а не «особенность»:

1. **Кадр** начинается с `04h` (MSG_START). Далее `LEN` (2 байта, **LE**),
   `CMD`/`ANSWER` (1 байт), `DATA` (N байт), `CRC16` (2 байта, **LE**).
2. `LEN = N + 1` — длина данных плюс один байт кода команды/ответа.
   Максимальный размер данных сообщения — **1536 байт**.
3. **CRC16-CCITT**: полином `0x1021`, начальное значение `0xFFFF`, MSB-first;
   считается по **всем байтам, кроме MSG_START**, то есть по `LEN..DATA`.
   В кадре передаётся младшим байтом вперёд.
4. **Код ответа** — младшие 7 бит байта `ANSWER`. **Старший бит (`0x80`) — бит
   предупреждения**, а не ошибка. Код нужно маскировать: `answer & 0x7F`.
5. Ответ с выставленным битом предупреждения — **успешный** ответ; детали
   предупреждений читаются командой `30h` (байт флагов).
6. Обмен инициирует только ККТ, ФН всегда отвечает. На один запрос — один
   ответ; ответ на предыдущую команду можно перечитать по `ENQ (05h)` на UART
   или повторным чтением на I2C.
7. UART: **115200 бит/с**, 8 бит данных, без чётности, 1 стоп-бит. После
   включения ФН всегда на 115200; повышенная скорость — командой `ABh` и только
   до перезапуска ФН.
8. I2C: ФН — slave с адресом **2**, рекомендуемая скорость 100 кбит/с,
   максимальный пакет 1542 байта (1536 данных + служебные поля).
9. Линия `SELECT`: соединена с GND — I2C; не подключена или на VIN — UART.
10. Любой ответ нужно проверять на: длину (`LEN`), CRC, код ответа. Молчаливо
    принимать «похожие» байты запрещено.

| `31h` | Номер ФН | — | ASCII 16 |

формируют фискальные документы и для тестера ФН обычно не нужны; их форматы —
в разделах 4.4–4.7 Протокола.

## Типы данных, на которых чаще всего ошибаются

- `DATE_TIME` — 5 байт: ГГ ММ ДД ЧЧ ММ, **десятичные** значения, год
  двухзначный. `DATE` — 3 байта: ГГ ММ ДД.
- `Uint16`, `Uint32`, `Uint40`, `Uint48` — **только LE**.
- `ASCII` — CP866, выравнивание по левому краю, дополнение нулями до полной
  длины; не гарантирует `\0` в конце, строку нужно ограничивать по длине поля.
- `TLV`/`STLV` — передаются целиком, дробить объект между командами нельзя.

Подробнее — `references/data-types.md`.

## Типичные ошибки

- Считать LEN или CRC в big-endian (по Протоколу оба поля — LE).
- Проверять код ответа без маски `0x7F` и отвергать корректный ответ с
  предупреждением.
- Считать ответ `3Dh` всегда 9-байтовым: третий байт (процент уведомлений)
  приходит только для ФН, активированного в режиме ФФД 1.2 с маркировкой.
- Требовать данные `3Dh` у ФН без поддержки маркировки и падать на длине.
- Путать этап применения ФН (1/3/7/15) с версией ФФД (0/1/3/4).
- Считать `33h` «тип ПО = 0» признаком МГМ как нормой Протокола: по документу
  это «опытный образец». Проект использует это как эвристику — не выдавай её за
  требование Протокола.
- Отправлять `3Bh` без корректной даты: команда не меняет время ФН, но дата
  должна быть не раньше даты активизации; при дате позже окончания срока
  вернётся `0`.
- Ждать ответ дольше таймаута и оставлять поток в состоянии RX.
- Считать, что `60h` (сброс МГМ) описана в Протоколе, — её там нет.

## Работа с этим репозиторием

Карта файлов и известные отклонения — `references/repo-integration.md`.
Коротко:

- кадры и CRC — `lib/fn/fn_helpers.c` (`calc_crc16`, `check_crc`);
- команды — `lib/fn/fn_commands.h` + `lib/fn/fn_tools.c`;
- разбор `30h`/`3Ah`/`33h` — `lib/fn/fn_objects/fn_info/fn.c`;
- разбор `32h`/`3Bh`/`3Dh` — `lib/fn/fn_objects/life_info/fn_life_info.c`;
- коды ошибок — `lib/fn/errors/fn_errors.{c,h}`;
- транспорт — `lib/fn/uart/fn_uart.c` (USART, DMA RX, таймаут);
- воркер — `lib/fn/fn_worker*.c`.

Перед изменением парсера:

1. Открой соответствующий раздел Протокола и выпиши смещения и длины полей.
2. Сверь с текущим кодом; при расхождении Протокол — источник истины.
3. Добавь/обнови `MU_TEST` с реальным ответом ФН (см. `unit_tests/`).
4. Проверь на устройстве (`FN_TESTS=1 ufbt launch`, `.test_scripts/units.py`).
5. Для изменяющих команд помни принцип I конституции: подтверждение
   пользователя обязательно.

## Чек-лист перед сдачей

- [ ] Кадр собран с `LEN`/CRC в LE и CRC по `LEN..DATA`.
- [ ] Ответ проверен по длине, CRC и коду с маской `0x7F`.
- [ ] Учтён бит предупреждения (`0x80`) и флаги из `30h`.
- [ ] Смещения и длины полей сверены с Протоколом, а не с догадкой.
- [ ] Учтены опциональные поля (`3Dh`, `A7h`) и этап применения ФН.
- [ ] Строки ASCII ограничены длиной поля и корректно завершены.
- [ ] Таймаут и отмена не оставляют поток UART в состоянии RX.
- [ ] Есть тест на реальном ответе ФН и прогон на устройстве.
