# Типы данных Протокола (приложение 5.5, Таблица 188)

| Тип | Длина | Описание | Пример |
|---|---|---|---|
| Byte | 1 | Беззнаковое целое | `01h` |
| DATE_TIME | 5 | ГГ ММ ДД ЧЧ ММ — десятичные значения в байтах | 20.07.2015 18:33 → `15 07 14 18 21` = `0Fh 07h 14h 12h 21h` |
| DATE | 3 | ГГ ММ ДД | 20.07.2015 → `15 07 20` |
| Uint16, LE | 2 | Беззнаковое 16-бит, LE | 1234 → `D2h 04h` |
| Uint32, LE | 4 | Беззнаковое 32-бит, LE | 12345678 → `4Eh 61h BCh 00h` |
| Uint40, LE | 5 | Беззнаковое 40-бит, LE | — |
| Uint48, LE | 6 | Беззнаковое 48-бит, LE (в таблице опечатка «8», фактическая длина 6) | — |
| DataN | N | Массив данных длины N | — |
| BCD | N | Строка BCD | 12345678 → `12h 34h 56h 78h` |
| ASCII | N | Строка ASCII в кодировке **CP866**, выравнивание по левому краю, дополнение `0` | — |
| TLV List | N | Список TLV-объектов | — |
| TLV | N | TLV-объект | — |

## Важные следствия для парсера

### DATE_TIME и DATE

- Год — **двузначный** (`year % 100`), век добавляется при отображении
  (`20%02u`).
- Значения хранятся как десятичные байты, а не BCD.
- В `3Bh` входной `DATE_TIME` содержит время, но Протокол предписывает его
  игнорировать.
- Невалидные даты (`00`, `13`-й месяц, 31 февраля) нужно проверять до
  форматирования — Протокол не гарантирует корректность содержимого.

### Целые

- Все многобайтовые целые в Протоколе — little-endian. Big-endian полей нет.
- В этом репозитории имена helper-функций исторически перепутаны:
  `two_uint8t_to_uint16t_BE()` читает младший байт первым и возвращает
  правильное LE-значение, а `two_uint8t_to_uint16t_LE()` — наоборот.
  **Не «исправляй» их по имени** — сломаешь парсинг. См. `repo-integration.md`.

### ASCII / CP866

- Строка может занимать всё поле без завершающего `\0`.
- Копировать нужно не более длины поля, затем принудительно ставить `\0`.
- CP866 — не UTF-8: при выводе на экран и в лог не полагайся на побайтовое
  совпадение с кириллицей UTF-8.

### TLV / STLV

- TLV передаются целиком: нельзя разбивать один объект на несколько команд
  `07h`.
- `45h`/`46h` и `44h`/`47h` отдают по одному объекту верхнего уровня за ответ;
  конец чтения — код `08h`.
- Протокол задаёт транспорт TLV, но не переопределяет теги: состав реквизитов и
  их кодирование — в ФФД (приказ ФНС от 14.09.2020 № ЕД-7-20/662@). Не выдумывай
  теги «по смыслу» — сверяйся с ФФД или с уже проверенными документами.
- В ответах `46h`/`47h` поле длины указано как `L+4`: это служебные байты
  заголовка плюс значение; при разборе учитывай заголовок, а не только `L`.

## Минимальные функции преобразования

Для прошивки достаточно:

```c
uint16_t u16le(const uint8_t* p) { return (uint16_t)p[0] | ((uint16_t)p[1] << 8); }
uint32_t u32le(const uint8_t* p) {
    return (uint32_t)p[0] | ((uint32_t)p[1] << 8) |
           ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24);
}
uint64_t u48le(const uint8_t* p) {
    uint64_t v = 0;
    for(int i = 5; i >= 0; --i) v = (v << 8) | p[i];
    return v;
}
```

Суммы `Uint40/Uint48` не помещаются в `uint32_t` — используй `uint64_t` и
форматируй в копейках/рублях явно, без потери разрядов.
