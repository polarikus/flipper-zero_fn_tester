# Служебные команды ФН (раздел 4.1–4.2 Протокола)

Во всех таблицах «выход» — это поле `DATA` ответа, без учёта `LEN`, `ANSWER` и
`CRC16`. Порядок байтов многобайтовых целых — **LE**, если не указано иное.

## 30h — Запрос статуса ФН

Входных параметров нет. Выход — 30 байт:

| Смещение | Поле | Тип | Длина |
|---|---|---|---|
| 0 | Состояние ФН (этап) | Byte | 1 |
| 1 | Текущий документ для ОФД | Byte | 1 |
| 2 | Данные документа | Byte | 1 |
| 3 | Состояние смены (0 — закрыта, 1 — открыта) | Byte | 1 |
| 4 | Флаги предупреждения | Byte | 1 |
| 5 | Дата и время последнего документа | DATE_TIME | 5 |
| 10 | Номер ФН | ASCII | 16 |
| 26 | Номер последнего ФД | Uint32, LE | 4 |

Состояние ФН — битовая маска этапа: `1` (этап 1), `3` (этап 2), `7` (этап 3),
`15` (этап 4).

Значения поля «Текущий документ для ОФД»:

| Код | Документ |
|---|---|
| `00h` | Нет открытого документа |
| `01h` | Отчёт о регистрации |
| `02h` | Отчёт об открытии смены |
| `04h` | Кассовый чек |
| `08h` | Отчёт о закрытии смены |
| `10h` | Отчёт о закрытии фискального накопителя |
| `11h` | Бланк строгой отчётности |
| `12h` | Отчёт об изменении параметров регистрации в связи с заменой ФН |
| `13h` | Отчёт об изменении параметров регистрации |
| `14h` | Кассовый чек коррекции |
| `15h` | БСО коррекции |
| `17h` | Отчёт о текущем состоянии расчётов |

Поле «Данные документа»: `0` — данных нет, `1` — данные получены. В Протоколе
это отдельный байт (смещение 2), который часто путают с состоянием смены.

Флаги предупреждений — см. `response-codes.md`.

## 31h — Запрос номера ФН

Входных параметров нет. Выход: `Номер ФН`, ASCII, 16 байт.

## 32h — Запрос срока действия ФН

Входных параметров нет. Выход — 5 байт:

| Смещение | Поле | Тип | Длина |
|---|---|---|---|
| 0 | Срок действия ФН (ГГ ММ ДД) | DATE | 3 |
| 3 | Сколько отчётов о регистрации/перерегистрации ещё можно сформировать | Byte | 1 |
| 4 | Сколько уже сформировано | Byte | 1 |

## 33h — Запрос версии ФН

Входных параметров нет. Выход — 17 байт:

| Смещение | Поле | Тип | Длина |
|---|---|---|---|
| 0 | Строка версии ПО ФН | ASCII | 16 |
| 16 | Тип ПО: `0` — опытный образец, `1` — серийное изделие | Byte | 1 |

Проект использует значение `0` как эвристику «МГМ»; Протокол такого признака не
определяет.

## 35h — Запрос последних ошибок ФН

Входных параметров нет. Выход: `DataN`, до 256 байт — детализация данных об
отказе. Данные предназначены для сохранения и передачи в сервис.

## 3Fh — Запрос исполнения ФН

Входных параметров нет. Выход: строка исполнения ФН, ASCII, 48 байт.

## 36h — Запрос счётчиков ФН (ФФД 1.1/1.2)

Вход: `Тип счётчиков`, Byte: `0` — счётчики текущей смены, `1` — счётчики ФН.

Выход:

| Поле | Длина |
|---|---|
| Номер смены или количество смен, Uint16 LE | 2 |
| Количество операций, Uint32 LE | 4 |
| Счётчики «приход» | 76 |
| Счётчики «возврат прихода» | 76 |
| Счётчики «расход» | 76 |
| Счётчики «возврат расхода» | 76 |
| Счётчики чеков коррекции | 44 |
| **Итого** | **386** |

Структура счётчиков кассовых операций (76 байт): количество операций Uint32 LE
(4), затем 12 сумм по Uint48 LE (по 6 байт): итоговая сумма, наличные,
электронные, предоплата, постоплата, встречное предоставление, НДС 18%, НДС
10%, НДС 0%, без НДС, расчётная ставка 18/118, расчётная ставка 10/110.

Структура счётчиков чеков коррекции (44 байта): количество всех коррекций
Uint32 LE, далее по паре «количество Uint32 LE + сумма Uint48 LE» для прихода,
возврата прихода, расхода, возврата расхода.

## 37h — Запрос счётчиков операций ФН (ФФД 1.1/1.2)

Вход: `Тип счётчиков`, Byte (`0`/`1`). Выход — 42 байта: номер смены/количество
смен Uint16 LE и 10 счётчиков Uint32 LE:

1. все чеки и чеки коррекции;
2. «приход»;
3. «возврат прихода»;
4. «расход»;
5. «возврат расхода»;
6. все чеки коррекции;
7. коррекции «приход»;
8. коррекции «возврат прихода»;
9. коррекции «расход»;
10. коррекции «возврат расхода».

## 38h — Запрос счётчиков по заданному типу расчётов

Вход: `Тип счётчиков` (Byte, `0`/`1`), `Тип расчёта` (Byte: `1` приход,
`2` возврат прихода, `3` расход, `4` возврат расхода).

Выход — 86 байт: структура счётчиков кассовых операций (76), количество чеков
коррекции Uint32 LE (4), итоговая сумма коррекций Uint48 LE (6).

## 39h — Итоги непереданных документов (ФФД 1.1/1.2)

Входных параметров нет. Выход — 44 байта: количество непереданных чеков и
коррекций Uint32 LE, далее по паре «количество Uint32 LE + сумма Uint48 LE» для
прихода, возврата прихода, расхода, возврата расхода.

Если ФН работает в режиме без передачи данных — ответ `08h` «Нет запрошенных
данных».

## 3Ah — Запрос формата ФН

Входных параметров нет. Выход — 2 байта:

| Смещение | Поле | Значения |
|---|---|---|
| 0 | Код формата ФФД, используемый в ФН | `0` — ФН не активизирован; `1` — ФН 1.2 в режиме ФФД-1.0/1.05; `3` — ФФД-1.1; `4` — ФФД-1.2 |
| 1 | Код максимальной поддерживаемой версии ФФД | для ФН 1.2 — `4` |

## 3Bh — Запрос оставшегося срока действия ФН

Вход: `Дата и время`, DATE_TIME (5 байт). Дата не может быть меньше даты
активизации ФН; поле времени игнорируется.

Выход: `Uint16 LE` — количество дней до истечения срока действия. Если дата в
запросе позже даты окончания — возвращается `0`.

Команда не изменяет дату и время, установленные в ФН.

## 3Dh — Запрос ресурса свободной памяти

Входных параметров нет. Выход:

| Смещение | Поле | Тип | Длина |
|---|---|---|---|
| 0 | Ресурс данных 5-летнего хранения (ориентировочное число документов) | Uint32 LE | 4 |
| 4 | Ресурс данных **30-дневного** хранения (свободная область, КБ) | Uint32 LE | 4 |
| 8 | Процент заполнения области уведомлений о маркировке | Byte | 1 (опционально) |

Третий байт возвращается **только** если ФН активирован в режиме поддержки
ФФД 1.2 (с маркировкой). Для остальных ФН ответ — 8 байт.

## A7h — Размер данных, переданных 07h/B7h

Входных параметров нет. Выход:

| Поле | Тип | Условие |
|---|---|---|
| Размер текущего документа для ОФД | Uint32 LE | всегда |
| Размер текущего уведомления о маркировке | Uint32 LE | только ФФД 1.2 |

## ABh — Повышенная скорость UART

Вход: `Скорость работы`, Uint32 LE (например, 921600). Выходных данных нет.
Действует до перезапуска ФН.

## 10h — Параметры текущей смены

Входных параметров нет. Выход — 5 байт:

| Смещение | Поле | Тип |
|---|---|---|
| 0 | Состояние смены (0 — закрыта, 1 — открыта) | Byte |
| 1 | Номер смены (закрытой — последней, открытой — текущей) | Uint16 LE |
| 3 | Номер чека (для закрытой смены — число документов в ней) | Uint16 LE |

Коды ответа: `02h` (только этап 2), `03h`, `04h`.

## 06h — Отменить документ

Входных параметров нет. Отменяет любой начатый фискальный документ; данные,
переданные `07h`, удаляются. Используется, чтобы не оставить ФН в состоянии
незавершённого документа.

## 07h — Передать данные документа

Вход: список TLV-объектов. ФН проверяет целостность TLV (длины должны
соответствовать фактическим), поэтому дробить TLV/STLV между вызовами нельзя.
Команду можно вызывать многократно; суммарный объём ограничен типом документа.
Полный форматно-логический контроль TLV ФН не выполняет.

## 04h / 05h — Закрытие ФН

`04h` начинает закрытие ФН, `05h` завершает его. Это изменяющие операции
2-го этапа; точные параметры и коды ответа — раздел 4.4.3–4.4.4 Протокола.
Для тестера ФН это опасные операции: без явного подтверждения пользователя их
выполнять нельзя.

## Формирование фискальных документов (общая схема, 4.3.1)

1. «Начать …» — команда начала конкретного документа;
2. один или несколько `07h` — передача TLV-данных;
3. «Завершить …» — формирование ФПД и завершение документа;
4. при необходимости — `06h` для отмены.

Документ формируется в едином цикле, без выключения питания; при сбое питании
процедуру начинают заново.
