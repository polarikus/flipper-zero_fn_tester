# Маркировка и уведомления (разделы 4.10–4.13 Протокола)

Раздел применим только к ФН, активированным в режиме поддержки ФФД 1.2 с
признаком работы с маркированными товарами. Если признак не установлен,
команды группы `Bxh` вернут `32h` «Запрещена работа с маркированными товарами».

Этот файл — карта раздела, а не замена Протоколу: точные форматы полей
приведены в указанных пунктах и зависят от типа КМ (типы 1–4) и версии ФФД.

## Команды

| Команда | Назначение | Раздел |
|---|---|---|
| `B0h` | Статус ФН по работе с кодами маркировки | 4.10.1 |
| `B1h` | Передать код маркировки для проверки в ФН | 4.10.2 |
| `B2h` | Сохранить результаты проверки КМ (в составе чека) | 4.10.3 |
| `B3h` | Очистить все результаты проверки КМ | 4.10.4 |
| `B5h` | Сформировать запрос о коде маркировки | 4.10.5 |
| `B6h` | Передать ответ на запрос о КМ | 4.10.6 |
| `B7h` | Передать данные для ФД с маркированными товарами | 4.10.7 |
| `BAh` | Получить состояние передачи уведомлений | 4.11.2 |
| `BBh` | Начать чтение уведомления о реализации маркированного товара | 4.11.1 |
| `BCh` | Прочитать блок данных уведомления | 4.11.1 |
| `BDh` | Отменить чтение уведомления | 4.11.1 |
| `BEh` | Завершить чтение уведомления | 4.11.2 |
| `BFh` | Передать квитанцию на уведомление | 4.11.3 |

## Общий алгоритм проверки КМ (4.10.1)

1. `B0h` — узнать состояние подсистемы маркировки и доступность операций.
2. `B1h` — передать КМ на проверку; для КМ типов 2 и 4 в параметрах передаются
   смещения до идентификатора применения GS1 «92» (байт `39h`), содержащего код
   проверки.
3. `B2h` — сохранить результаты проверки в составе формируемого чека.
4. При необходимости `B3h` — очистить таблицу результатов проверки.
5. `B5h` — сформировать запрос о КМ (документ для ОИСМ).
6. `B6h` — передать полученный ответ на запрос.
7. `B7h` — передать данные для ФД, содержащих сведения о маркированных товарах
   (доп. код команды выбирает назначение: документ для ОФД или уведомление для
   ОИСМ).

`B7h` имеет дополнительный код (1, 2 или 3), который определяет, какие данные
формируются. Для документов ФФД 1.2 часть реквизитов формирует сам ФН — ККТ не
должна их передавать (списки в 5.3/5.4 Протокола).

## Уведомления о реализации (4.11)

Постраничное чтение: `BBh` (начать) → `BCh` (блок данных, повторять) → `BEh`
(завершить) либо `BDh` (отменить). `BAh` показывает состояние передачи.
`BFh` передаёт квитанцию на уведомление. Выгрузка уведомлений для ККТ в
автономном режиме описана в 4.12.

## АС ОКП (4.13)

Процедуры получения сетевого адреса АС ОКП, обновления ключей проверки КМ и
взаимодействия с сервером АС ОКП описаны в 4.13.1–4.13.5. Они относятся к
инфраструктуре ОИСМ и для тестера ФН не нужны.

## Коды ответа, специфичные для маркировки

| Код | Значение |
|---|---|
| `32h` | Запрещена работа с маркированными товарами (при активации не установлен признак) |
| `33h` | Неверная последовательность команд группы `Bxh` |
| `34h` | Работа с маркировкой временно заблокирована: область уведомлений заполнена |
| `35h` | Переполнена таблица проверки КМ (не более 128 КМ в чеке) |
| `36h` | Превышен период 90 дней с последнего обновления ключей проверки |
| `3Ch` | Неверный TLV-тег / в блоке отсутствуют необходимые реквизиты |
| `3Eh` | КМ, переданный в реквизите 2007, ранее не проверялся в ФН |

## Минимум для тестера ФН

Тестеру ФН достаточно:

- `B0h` — показать, доступна ли маркировка и не заблокирована ли она;
- `3Dh` — показать процент заполнения области уведомлений (только ФФД 1.2).

Полноценная работа с КМ (проверка, запросы, уведомления) — вне области
диагностического приложения и требует интеграции с ОИСМ.
