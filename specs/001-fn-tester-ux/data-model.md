# Phase 1 — Data Model: сущности, поля, состояния, валидация

**Feature**: `001-fn-tester-ux` | **Дата**: 2026-10-29
**Источник**: `spec.md` (Key Entities), Протокол ФН v1.2.05 (разделы 3.4, 4.2),
решения `research.md` D1–D11.

Модель делится на три уровня:

1. **Провод** — кадр и его поля (`FnFrame`), без интерпретации.
2. **Протокол** — типизированные снимки ответов (`FnStatus`, `FnIdent`,
   `FnLife`, `FnSession`) с флагами достоверности.
3. **Приложение/UI** — агрегаты (`FnInfo`, `FnLifeInfo`), операция (`FnOperation`)
   и модели экранов (`FnMenuModel`, `FnTextModel`, `FnWaitModel`,
   `FnConfirmModel`).

---

## 1. Базовые типы (`lib/fn/core/fn_types.h`)

### 1.1 `Date` / `DateTime`

| Поле | Тип | Допустимый диапазон | Примечание |
|---|---|---|---|
| `year` | `uint8_t` | 0–99 | две последние цифры года, десятичное значение |
| `month` | `uint8_t` | 1–12 | исправлено с `mouth` |
| `day` | `uint8_t` | 1–31 | без проверки числа дней в месяце |
| `hour` | `uint8_t` | 0–23 | только `DateTime` |
| `minute` | `uint8_t` | 0–59 | только `DateTime` |

`bool fn_date_is_valid(const Date*)`, `bool fn_datetime_is_valid(const DateTime*)`
— общие для парсеров и UI. `year == 0` в `32h` означает «ФН не активизирован».

### 1.2 `FnStage` — этап жизни ФН (поле `Состояние ФН`, `30h`, смещение 0)

| Значение на проводе | Enum | Русская подпись |
|---|---|---|
| `0x01` | `FnStageReadyRegistration` | «Готов к регистрации» |
| `0x03` | `FnStageRegistered` | «Зарегистрирован» |
| `0x07` | `FnStageArchiveClosed` | «Архив закрыт, ждёт передачи в ОФД» |
| `0x0F` | `FnStageArchiveClosedFinal` | «Архив ФН закрыт» |
| иное | `FnStageUnknown` | «Неизвестный этап (0xNN)» |

Правило: значение — битовая маска; сравнение только по полному значению,
побитовые проверки не используются.

### 1.3 `FnFfd` — версия ФФД (`3Ah`)

| Код | Enum | Подпись |
|---|---|---|
| `0` | `FnFfdNone` | «Не активизирован» |
| `1` | `FnFfd1_05` | «1.05» |
| `3` | `FnFfd1_1` | «1.1» |
| `4` | `FnFfd1_2` | «1.2» |
| иное | `FnFfdUnknown` | «Неизвестно (0xNN)» |

### 1.4 `FnDocCode` — текущий документ для ОФД (`30h`, смещение 1)

| Код | Enum | Русская подпись |
|---|---|---|
| `0x00` | `FnDocNone` | «Документа нет» |
| `0x01` | `FnDocRegistration` | «Отчёт о регистрации» |
| `0x02` | `FnDocSessionOpen` | «Отчёт об открытии смены» |
| `0x04` | `FnDocReceipt` | «Кассовый чек» |
| `0x08` | `FnDocSessionClose` | «Отчёт о закрытии смены» |
| `0x10` | `FnDocFnClose` | «Отчёт о закрытии ФН» |
| `0x11` | `FnDocStrictReport` | «Бланк строгой отчётности» |
| `0x12` | `FnDocRegChangeFnReplace` | «Изменение регистрации при замене ФН» |
| `0x13` | `FnDocRegChange` | «Изменение параметров регистрации» |
| `0x14` | `FnDocReceiptCorrection` | «Кассовый чек коррекции» |
| `0x15` | `FnDocStrictReportCorrection` | «БСО коррекции» |
| `0x17` | `FnDocCurrentSettlements` | «Отчёт о текущем состоянии расчётов» |
| иное | `FnDocUnknown` | «Неизвестный документ (0xNN)» |

### 1.5 `FnWarnFlags` — флаги предупреждений (`30h`, смещение 4)

| Бит | Маска | Enum | Русская подпись |
|---|---|---|---|
| 0 | `0x01` | `FnWarnReplaceSoon` | «Срочная замена ФН (≤3 дней)» |
| 1 | `0x02` | `FnWarnResourceSoon` | «Исчерпание ресурса ФН (≤30 дней)» |
| 2 | `0x04` | `FnWarnMemoryFull` | «Память ФН заполнена на 99 %» |
| 3 | `0x08` | `FnWarnOfdTimeout` | «Превышено время ожидания ОФД» |
| 4 | `0x10` | `FnWarnOfdFormatLogic` | «Отказ по форматно-логическому контролю» |
| 5 | `0x20` | `FnWarnNeedSetup` | «Требуется настройка ККТ» |
| 6 | `0x40` | `FnWarnOfdCancelled` | «ОФД аннулирован» |
| 7 | `0x80` | `FnWarnReserved` | не интерпретируется; попадает в «Прочие предупреждения» |

Тексты флагов формируются в UI: `core` отдаёт только соответствие
«бит → русский текст» (`fn_warn_flag_text(mask)`), а `ui/fn_format.c` собирает
блок: известные флаги построчно, затем `Прочие предупреждения: 0xNN` при
ненулевых неописанных битах. Флаги **не** являются ошибкой операции.

### 1.6 `FNError` — код ответа ФН

| Поле | Тип | Примечание |
|---|---|---|
| `code` | `uint8_t` | `answer & 0x7F`, значения `00h`–`3Eh` |
| `title` | `const char*` | короткий русский текст (≤ ~40 символов) |
| `hint` | `const char*` | рекомендация; `""`, если не нужна |

Инвариант: для каждого кода из `response-codes.md` есть запись; для прочих —
`fn_error_is_known() == false` и UI печатает
«Неизвестный код ответа ФН: 0xNN». Код `00h` — успех, текст не показывается.

## 2. Снимки ответов (уровень протокола, `lib/fn/proto/`)

### 2.1 `FnStatus` — ответ `30h` (30 байт)

| Смещение | Поле протокола | Поле структуры | Тип | Наличие |
|---|---|---|---|---|
| 0 | Состояние ФН | `stage` | `FnStage` | обязательное |
| 1 | Текущий документ для ОФД | `current_doc` | `FnDocCode` | обязательное |
| 2 | Данные документа | `doc_data_received` | `bool` | обязательное |
| 3 | Состояние смены | `session_open` | `bool` | обязательное |
| 4 | Флаги предупреждения | `warn_flags` | `uint8_t` | обязательное |
| 5–9 | Дата/время последнего документа | `last_doc_dt` | `DateTime` | `has_last_doc` |
| 10–25 | Номер ФН (ASCII CP866, 16) | `serial[17]` | `char` | `has_serial` |
| 26–29 | Номер последнего ФД | `last_doc_number` | `uint32_t` LE | `has_last_doc_number` |

Валидация: `len >= 30`; SN копируется 16 байт + `'\0'` в `[16]`, в UI
отображается до первого `'\0'`; дата валидна по 1.1, иначе `has_last_doc=false`
(и `has_last_doc_number=false`, так как они относятся к одному документу).

### 2.2 `FnSession` — ответ `10h` (5 байт)

| Смещение | Поле | Тип | Наличие |
|---|---|---|---|
| 0 | Состояние смены | `bool` | обязательное |
| 1–2 | Номер смены | `uint16_t` LE | обязательное |
| 3–4 | Номер чека | `uint16_t` LE | обязательное |

Используется только для этапа 2 (FR-027). Отказ `02h`/`03h`/`04h` → поля
помечаются недоступными, остальные блоки экрана сохраняются.

### 2.3 `FnFfdInfo` — ответ `3Ah` (2 байта) и `FnFwInfo` — ответ `33h` (17 байт)

| Структура | Поле | Источник | Тип |
|---|---|---|---|
| `FnFfdInfo` | `current` | `3Ah[0]` | `FnFfd` |
| `FnFfdInfo` | `max` | `3Ah[1]` | `FnFfd` |
| `FnFwInfo` | `version[17]` | `33h[0..15]` + `'\0'` | `char` |
| `FnFwInfo` | `mode_raw` | `33h[16]` | `uint8_t` (0 — опытный, 1 — серийный) |
| `FnFwInfo` | `is_mgm` | производное `mode_raw == 0` | `bool` (эвристика проекта) |

`is_mgm` документируется как проектная эвристика, а не требование Протокола.

### 2.4 `FnLifeDate` — ответ `32h` (5 байт)

| Смещение | Поле | Тип | Наличие |
|---|---|---|---|
| 0–2 | Срок действия (ГГ ММ ДД) | `Date` | обязательное; `year == 0` → «не активизирован» |
| 3 | Осталось отчётов о регистрации | `reg_remaining` | обязательное |
| 4 | Выполнено отчётов о регистрации | `reg_done` | обязательное |

### 2.5 `FnLifeDays` — ответ `3Bh` (2 байта)

| Поле | Тип | Наличие |
|---|---|---|
| `days` | `uint16_t` LE | `has_days` |

Правило: `days == 0` → `has_days = false`, в UI «нет данных» (FR-011).
Запрос выполняется на **любом** этапе жизни (FR-011) с датой из RTC не раньше
даты активизации; если ФН отказывает в ответе, `has_days = false` и UI
показывает «нет данных», а не ошибку операции.

### 2.6 `FnMemory` — ответ `3Dh` (8 или 9 байт)

| Смещение | Поле | Тип | Наличие |
|---|---|---|---|
| 0–3 | Ресурс 5-летнего хранения (документы) | `five_year_documents` | обязательное |
| 4–7 | Ресурс **30-дневного** хранения (КБ) | `thirty_day_kb` | обязательное |
| 8 | Процент заполнения области уведомлений о маркировке | `marking_percent` | `has_marking` (`len >= 9`) |

Валидация: `len == 8` или `len == 9`; иное — `false`. Абсолютный запрет
чтения `data[8]` при `len == 8` (дефект текущего кода).

## 3. Агрегаты приложения

### 3.1 `FnInfo` — всё, что показывает экран «Информация об ФН»

| Поле | Тип | Источник | Наличие |
|---|---|---|---|
| `status` | `FnStatus` | `30h` | обязательное для экрана |
| `ffd` | `FnFfdInfo` | `3Ah` | `has_ffd` |
| `fw` | `FnFwInfo` | `33h` | `has_fw` |
| `session` | `FnSession` | `10h` | `has_session` |
| `response_has_warning` | `bool` | `ANSWER & 0x80` последнего ответа | — |

Правила отображения (FR-007, FR-008, FR-026, FR-027):
- SN, этап, смена, флаги — из `30h` всегда;
- текущий документ для ОФД: `FnDocCode` + «данные получены / не получены»;
- ФФД и версия ПО — только при `has_ffd`/`has_fw`, иначе «нет данных»;
- номер и дата последнего ФД — только при `has_last_doc` (этапы 2 и 3);
- номер смены/чека — только для этапа 2 и `has_session`, иначе
  «нет данных»;
- блок предупреждений — при `warn_flags != 0`.

### 3.2 `FnLifeInfo` — экран «Информация о фазе жизни ФН»

| Поле | Тип | Источник | Наличие |
|---|---|---|---|
| `date` | `FnLifeDate` | `32h` | обязательное |
| `days` | `FnLifeDays` | `3Bh` | `has_days` |
| `memory` | `FnMemory` | `3Dh` | `has_memory` |

Правила: показатели запрашиваются независимо от версии ФФД и этапа; отказ
отдельной команды не скрывает остальные блоки; процент маркировки — только
при `has_marking` (FR-011, FR-028, SC-013, SC-014).

### 3.3 Связи

```text
FnFrame (провод)
   │ parse
   ├── FnStatus   ─┐
   ├── FnFfdInfo  ─┤
   ├── FnFwInfo   ─┼──> FnInfo ──> FnTextModel ──> FnTextView
   ├── FnSession  ─┘
   ├── FnLifeDate ─┐
   ├── FnLifeDays ─┼──> FnLifeInfo ──> FnTextModel ──> FnTextView
   └── FnMemory   ─┘

FNError ──> FnTextModel (результат/ошибка)
FnOperation ──> событие воркера ──> сцена ──> экран
```

## 4. Операция обмена (`FnOperation`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `uint32_t` | монотонный номер запуска; защита от «поздних» событий |
| `kind` | `FnOpKind` | `Detect`, `ReadInfo`, `ReadLife`, `FlashMgm` |
| `status` | `FnOpStatus` | итог операции |
| `error` | `FNError` | код ответа ФН (0, если ответа не было) |
| `has_warning` | `bool` | старший бит ответа |
| `deadline_tick` | `uint32_t` | `furi_get_tick()` + дедлайн |
| `cancellable` | `bool` | `false` только для `FlashMgm` |
| `task` | `FnTask*` | владелец выходных данных (выделяет вызывающий) |

### 4.1 Состояния операции

```text
Idle
 └─ start(kind) ─> Running
                     ├─ (все команды Ok, данные разобраны) ─> Completed(Ok)
                     ├─ (истёк дедлайн / нет байт)         ─> Completed(NoResponse)
                     ├─ (код ответа != 00h)               ─> Completed(FnRefused)
                     ├─ (кадр битый / CRC / LEN)          ─> Completed(BadFrame)
                     ├─ (cancel(), kind != FlashMgm)      ─> Completed(Cancelled)
                     └─ (cancel(), kind == FlashMgm)      ─> остаётся Running
Completed ─> callback(результат) ─> Idle
```

Инварианты:
- одновременно активна не более одной операции (`fn_worker_is_busy`);
- callback вызывается ровно один раз на `start`, включая исход `Cancelled`;
- после `Completed` воркер всегда возвращается в `Idle` и очищает UART
  (`fn_uart_cancel`), даже при ошибке;
- `FlashMgm` не повторяется и не отменяется по Back; по дедлайну 30 с
  завершается `NoResponse`;
- событие с чужим `id` игнорируется сценой (логируется `FURI_LOG_W`).

### 4.2 Потоки и владение

| Объект | Кто создаёт | Кто освобождает | Поток |
|---|---|---|---|
| `FNWorker` | `fn_test_app_alloc` | `fn_test_app_free` | — |
| `FnInfo` / `FnLifeInfo` | `FNApp` (`*_alloc`) | `FNApp` (`*_free`) | читает UI-поток, пишет воркер (через завершённую операцию) |
| `FnTask` | сцена/`FNApp` | владелец после события | — |
| RX-буфер | `transport` | `transport` | поток UART |
| `FnTextModel` | view | view | GUI-поток |

Правило: воркер заполняет `task` только пока операция `Running`; UI читает
`task` только после события завершения. Одновременного доступа нет.

## 5. Модели экранов (`ui/`)

### 5.1 `FnMenuModel`

| Поле | Тип | Правило |
|---|---|---|
| `selected` | `uint8_t` | 0–4, сохраняется между входами |
| `items[5]` | `const char*` | фиксированный порядок FR-001 |

Пункты: «Информация об ФН», «Информация о фазе жизни ФН», «Очистка МГМ»,
«Распиновка», «О приложении».

### 5.2 `FnTextModel` — универсальный прокручиваемый экран

| Поле | Тип | Правило |
|---|---|---|
| `sections[FN_TEXT_MAX_SECTIONS]` | `FnTextSection` | ≤8 секций |
| `section_count` | `uint8_t` | — |
| `scroll_y` | `uint16_t` | 0..`content_height - viewport_height` |
| `content_height` | `uint16_t` | вычисляется при сборке |

`FnTextSection`: `title` (может быть `NULL`), `lines[FN_TEXT_MAX_LINES]`,
`line_count`. `FnTextLine`: `text[FN_TEXT_LINE_LEN]` (40), `emphasis` (обычная /
заголовок / предупреждение).

Правила вёрстки:
- заголовок секции всегда рисуется вместе с первой строкой (перенос заголовка
  на новую страницу, если не помещается);
- длинная строка переносится по словам; обрезка без потери смысла запрещена
  (FR-025);
- шаг прокрутки = высота строки используемого шрифта;
- `scroll_y` сбрасывается при новой сборке модели.

### 5.3 `FnWaitModel`

| Поле | Тип | Правило |
|---|---|---|
| `mode` | `FnWaitMode` (`Detect`, `Read`, `Flash`) | определяет текст |
| `cancelable` | `bool` | `false` для `Flash` (FR-023) |
| `title[32]` | `char` | «Поиск ФН…», «Ожидание ответа ФН…», «Очистка МГМ…» |
| `subtitle[96]` | `char` | для `Flash`: «Может занять до 30 секунд, не прерывайте» (73 байта UTF-8; в 48 байт строка обрезалась — Фаза 5, `baseline.md` §6.5) |
| `progress` | `uint8_t` | 0 — не показывать |

Анимация: `IconAnimation` с `A_FNLooking_64x64`, запускается в `enter`,
останавливается в `exit`; модель анимацию не хранит.

### 5.4 `FnConfirmModel`

| Поле | Тип | Правило |
|---|---|---|
| `title[32]` | `char` | «Очистка МГМ» |
| `body[128]` | `char` | «Операция необратима…» |
| `selected` | `uint8_t` | 0 — «Отмена», 1 — «Очистить» (по умолчанию 0) |

## 6. Правила валидации (сводно)

| Объект | Правило | Реакция на нарушение |
|---|---|---|
| Кадр | `buf[0] == 0x04` | `FnFrameWrongStart`, операция `BadFrame` |
| Кадр | `LEN == len - 5` | `FnFrameLengthMismatch` |
| Кадр | CRC по `LEN..DATA` совпадает с `u16le` в конце | `FnFrameWrongCrc` |
| Кадр | `6 <= len <= 256` | `FnFrameTooShort`/`TooLong` |
| Кадр | `code = answer & 0x7F`, `has_warning = answer & 0x80` | — |
| `30h` | `len >= 30` | `false`, блок считается недоступным |
| `32h` | `len == 5` | `false` |
| `33h` | `len == 17` | `false` |
| `3Ah` | `len == 2` | `false` |
| `3Bh` | `len == 2` | `false` |
| `3Dh` | `len == 8 \|\| len == 9` | `false` |
| `10h` | `len == 5` | `false` |
| SN / версия ПО | ровно 16 байт, `'\0'` в `[16]` | строка обрезается по первому `'\0'` |
| Дата | диапазоны 1.1 | `has_* = false`, в UI «нет данных» |
| Дни до конца | `0` — не значение | «нет данных» |
| Процент маркировки | только при `len >= 9` | строка не показывается |
| Ответ с предупреждением | `has_warning` | успех + блок предупреждений |
| Неизвестный код | нет в каталоге | «Неизвестный код ответа ФН: 0xNN» |
| Очистка МГМ | `is_mgm == true` | иначе команда не отправляется |

## 7. Состояния приложения (сцены)

```text
Start (меню)
 ├─ «Информация об ФН»          ─> Wait(Detect→ReadInfo) ─> Info
 ├─ «Информация о фазе жизни»   ─> Wait(Detect→ReadLife) ─> Life
 ├─ «Очистка МГМ»               ─> Wait(Detect)
 │                                   ├─ не МГМ ─> Result(недоступно) ─> Start
 │                                   └─ МГМ    ─> Confirm
 │                                                  ├─ Отмена ─> Start
 │                                                  └─ Очистить ─> Wait(Flash) ─> Result
 ├─ «Распиновка»                ─> Wiring ─> Start
 └─ «О приложении»              ─> About  ─> Start
```

Правила Back:
- `Wait` при `cancelable == true` → отмена операции и выход в `Start` (≤1 с);
- `Wait` при `cancelable == false` → игнорируется, ждём результат;
- `Info`, `Life`, `Result`, `Wiring`, `About`, `Confirm` → сразу `Start`;
- `Start` + Back → выход из приложения.

Примечание: `Detect` и `Read` могут выполняться в одной сцене `Wait` с разными
`FnWaitMode`; отдельные сцены для детекта и результата не нужны.
