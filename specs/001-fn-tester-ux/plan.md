# Implementation Plan: Русскоязычный интерфейс тестера ФН + полный рефакторинг `lib/fn` и UI

**Branch**: `001-fn-tester-ux` | **Date**: 2026-10-29 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-fn-tester-ux/spec.md` и требование
пользователя: «полный рефакторинг текущего кода на твоё усмотрение; особенно важно
исправить путаницу `*_LE`/`*_BE` в `fn_helpers.c`; в UI сохранить логическую
целостность блоков и анимацию подключения ФН».

## Summary

Приложение переводится на полностью русский интерфейс с собственной отрисовкой
(меню, экран ожидания с анимацией, прокручиваемые блоки информации, подтверждение
очистки МГМ) и одновременно переписывается целиком: `lib/fn` разделяется на
чистое ядро (байтовый порядок, кадр, CRC, парсеры, каталог ошибок), транспорт
(UART/DMA/таймауты/отмена) и воркер операций; сцены и view заменяются на
набор из четырёх кастомных экранов.

Ключевое техническое решение — **атомарная замена байтового слоя**: функции с
перепутанными именами `two_uint8t_to_uint16t_LE/BE` и `uint16t_LE/BE_to_uint8t_bytes`
удаляются вместе с «хотфиксом» `end = end - 1` в `calc_crc16()` и байтовой
перестановкой в возвращаемом значении; вводится канонический слой `fn_wire`
(`u16le/u32le get/put`, `crc16_ccitt` как числовое значение MSB-first) и
`fn_frame` (сборка/разбор кадра). Поведение на проводе не меняется — это
доказывается golden-кадрами из `.opencode/skills/fn-protocol/examples/frames.md`
до и после замены.

## Technical Context

**Language/Version**: C (стандарт SDK Flipper Zero, C11-совместимый), сборка
только `ufbt`; локальный SDK — `~/.ufbt/current` (`f7-update-1.5.1`, канал
`release`).

**Primary Dependencies**: `furi`, `gui` (ViewPort/Canvas/ViewDispatcher/
SceneManager), `expansion` (`RECORD_EXPANSION`, отключается на время работы),
приватная библиотека `lib/fn` (`Lib(name="fn")`); ассеты `fap_icon_assets`
(иконки и анимация) + новый встроенный u8g2-шрифт с кириллицей.

**Storage**: не используется. Состояния — только RAM-модели; persistent-данных
нет, `furi_record_open(RECORD_STORAGE)` не требуется.

**Testing**: два уровня.
1. On-device minunit (`FN_TESTS=1 ufbt launch` + `.test_scripts/units.py`) —
   транспорт, воркер, реальный ФН (с `[SKIP]` при отсутствии ответа).
2. Новые host-тесты (`make -C tests/host`) для чистого ядра `core/`/`proto/` и
   для GUI-независимых частей UI (`fn_strings.h`, `fn_text_model.h`,
   `fn_format.c`): golden-кадры, CRC, парсеры, каталог ошибок, границы буферов,
   сборка секций экранов. Эти модули не включают `gui/` и `furi`, поэтому
   компилируются `cc` на macOS.

**Target Platform**: Flipper Zero, STM32WB55 (Cortex-M4F), 256 КБ RAM, 1 МБ
flash, экран 128×64, 1 бит/пиксель. Внешний FAP (`appid = fn_test`,
`FlipperAppType.EXTERNAL`, категория `GPIO`).

**Performance Goals**: информация о ФН — не более 5 с от выбора пункта меню
(SC-001); отмена ожидания чтения — не более 1 с (SC-003); отсутствие ответа
диагностируется за ≤10 с для чтения и ≤30 с для очистки МГМ (SC-006);
UI-поток не блокируется ни на одном экране (анимация не «замерзает»).

**Constraints**: кадр ≤256 байт (`FN_FRAME_MAX_LEN`), данные сообщения по
Протоколу ≤1536 байт (в приложении не используются); никаких аллокаций по
длине, пришедшей извне; стек воркера 10240, стек UART-потока 1024
(пересматривается по `top`), стек приложения 4096; бюджет нового шрифта ≤6 КБ
RAM; суммарный прирост RAM после рефакторинга ≤12 КБ (проверка `free`
до/после).

**Scale/Scope**: ~35 файлов, ~3.5 kLOC; целевой объём — 4 модуля `lib/fn`,
4 кастомных view, 8 сцен, ~120 новых тестовых проверок.

*GATE: проверка до Phase 0 и повторная проверка после Phase 1.*

| Принцип | Как соблюдается в плане | Статус |
|---|---|---|
| **I. Безопасность ФН** (NON-NEGOTIABLE) | Единственная изменяющая команда — `60h`; перед ней обязательная проверка «МГМ/боевой» по данным `30h`/`33h` и подтверждение в UI (FR-012, FR-024). Команда отправляется ровно один раз, повтор при ошибке запрещён. Коды команд остаются только в `lib/fn/proto/fn_commands.h`; сцены не содержат байтов команд. Все коды ответа получают русское описание. | PASS |
| **II. Слоистая архитектура** | Явные границы модулей: `core/` (чистая арифметика, без `furi`) → `proto/` (парсеры, без UART) → `transport/` (только HAL serial) → `worker/` (операции и события) → `ui/` (сцены и view). Сцены общаются только с `fn_worker`, не с UART и не с парсерами кадров. `lib/fn` не знает про `FNApp`. Правило зафиксировано в `contracts/module-boundaries.md`. | PASS |
| **III. Детерминированные потоки, UART и ошибки** | Каждая операция имеет дедлайн: 300 мс на служебную команду, 10 с на операцию чтения, 30 с на очистку МГМ; ожидание `rx_ready` ограничено 100 мс; ответ трактуется как `answer & 0x7F`, бит `0x80` — предупреждение. Отмена операции не оставляет UART в состоянии RX (явный `fn_uart_cancel`, сброс флагов и буфера). `expansion_disable/enable` — парные. Логи через `TAG`/`FURI_LOG_*`, консоль не отключается. | PASS (после R4–R5) |
| **IV. Тестирование на устройстве** (NON-NEGOTIABLE) | Каждый новый модуль `core/`/`proto/` покрыт host-тестами и `MU_TEST` на устройстве; набор регистрируется в `unit_tests/test_index.c`. Тесты, требующие ФН, печатают `[SKIP]`. Прогон обязан давать `Status: PASSED`, `Failed tests: 0`, `Leaked` без роста. Дополнительно — реальный ФН для приёмки US1–US4. | PASS |
| **V. Память и ресурсы** | Все буферы фиксированного размера; `malloc` только под объекты моделей с парным `free`; аллокации по внешней длине запрещены (проверяется тестом «ответ длиннее буфера»). Стек UART-потока пересматривается обоснованно. Прирост RAM от шрифта и новых моделей измеряется `free`/`top` и ограничен бюджетом. | PASS |

Нарушений, требующих обоснования исключений, нет. Текущие отклонения (см.
`research.md`, D1–D3) устраняются в рамках плана, а не принимаются как долг.

### Повторная проверка после Phase 1

Дизайн (`data-model.md`, `contracts/*`) не вводит нарушений: границы модулей
совпадают с принципом II, все контракты содержат ограничения по времени и
памяти, изменяющая команда обёрнута обязательным подтверждением и preflight-
проверкой. **GATE: PASS.**

### Синхронизация конституции (PATCH)

Конституция 1.0.0 упоминает конкретные имена, которые меняются при полном
рефакторинге. Смысл принципов не меняется, поэтому требуется поправка PATCH
(уточнение формулировок) до этапа R1:

| Принцип | Было | Стало |
|---|---|---|
| II | `lib/fn/fn_tools.c`, `lib/fn/fn_helpers.c`, `lib/fn/uart` | `core/` (кадр, байты, ошибки), `proto/` (парсеры), `transport/` (UART) |
| III | `FNRxTimeout`, `FNToolTimeout`, `FNCustomEventWorkerFNNotResponse` | `FnOpStatusNoResponse`, `FnFrameStatus`, `FNCustomEventWorkerResult` |
| V | `FN_UART_MIN_PACKAGE_LEN`, `FN_UART_MAX_PACKAGE_LEN` | `FN_FRAME_MAX_LEN`, `FN_FRAME_MAX_PAYLOAD` |

Поправка вносится через `/speckit.constitution` и не меняет ни одного
требования по существу; до её принятия план считается совместимым с
конституцией по смыслу.

### Порядок работ (этапы рефакторинга)

Каждый этап заканчивается «зелёным» состоянием: `ufbt` без warning-ов,
`ufbt lint`, host-тесты, on-device тесты, `free` без утечек.

| Этап | Содержание | Критерий приёмки этапа |
|---|---|---|
| **R0. Базовая линия** | Зафиксировать golden-кадры и текущее поведение; добавить `tests/host` с тестами на существующие helper'ы (включая тест-«ловушку»); измерить `free`/`top`, снять baseline `Leaked`. | Host-тесты воспроизводят текущее поведение; baseline (`free`, `top`, `Leaked`) зафиксирован в отчёте этапа/PR. |
| **R1. Кадр и байты** | Новые `core/fn_wire` и `core/fn_frame`; удаление старых helper'ов, `end-1` и swap в CRC; перевод сборки/разбора кадра; первая версия `docs/byte-order.md`. | Побайтовое совпадение всех запросов из golden-набора; CRC всех эталонных ответов проходит проверку; host+device тесты зелёные; ловушка задокументирована. |
| **R2. Парсеры** | `proto/*` с таблицами смещений, флагами `has_*` и проверками границ; удаление разбора из старого `fn_tools.c`; `10h` для смены/чека; `3Dh` 8/9 байт. | Тесты на каждый эталонный ответ; тест «нет чтения за границей»; частичные данные не теряются. |
| **R3. Ошибки** | Полный каталог кодов v1.2.05, русские title/hint, «Неизвестный код ответа ФН: 0xNN». | Тест на каждый код таблицы и на неизвестный код; ни один код не остаётся без текста. |
| **R4. Транспорт** | Один stream-буфер, one-shot таймер, отсутствие блокирующей отправки из колбэка, приоритет потока, `fn_uart_cancel`, ошибка инициализации вместо `furi_check`-краша. | Тесты UART на устройстве; отмена возвращает транспорт в Idle; занятый порт не роняет приложение. |
| **R5. Воркер** | Типизированные операции (`FnOpKind`), дедлайны 10/30 с, отмена, события с результатом, снимки `FnInfo`/`FnLifeInfo`. | Отмена ≤1 с; после 10 циклов «операция→отмена» следующая операция успешна (SC-005); нет зависаний при остановке потока. |
| **R6. UI** | Шрифт с кириллицей, 4 кастомных view, 8 сцен, русские строки, прокрутка секциями, сохранённая анимация подключения, подтверждение и неотменяемое ожидание МГМ. | Все сценарии US1–US5 на устройстве; текст читается; Back ведёт себя по FR-015/FR-018/FR-025. |
| **R7. Приложение** | Уборка `FNApp` (мёртвые record/view/mode), `fn_info_alloc/free`, порядок free, манифест и версия. | `free` после выхода равен baseline; в release нет отладочных пунктов. |
| **R8. Документация** | `docs/*`, `AGENTS.md`, `README.md`, `.catalog/CHANGELOG.md`, версия 0.6. | Документы соответствуют коду; чек-лист приёмки пройден. |

## Ключевые технические решения (кратко; обоснования — `research.md`)

1. **Байтовый слой**: `fn_wire_u16le_get/put`, `fn_wire_u32le_get/put`,
   `fn_wire_crc16_ccitt(data, len)` (числовое значение, MSB-first, без swap).
   Старые имена удаляются, алиасы не вводятся. `calc_crc16` с `end = end - 1`
   исчезает: API переходит на длину. Причина и история — `docs/byte-order.md`.
2. **Кадр**: `fn_frame_build()` в буфер вызывающего, `fn_frame_parse()` — view на
   принятый буфер с проверками `MSG_START`, `LEN`, `CRC`; код ответа и признак
   предупреждения — поля `code` (`answer & 0x7F`) и `has_warning`.
3. **Парсеры** возвращают не «успех/провал», а структуру с флагами достоверности
   (`has_serial`, `has_last_doc`, `has_days_to_end`, `has_marking`, …), чтобы UI
   показывал «нет данных» вместо мусора (FR-011, FR-027).
4. **Воркер** держит одну активную операцию с `op_id`; результат приходит
   событием с типизированным `FnOpResult`; отмена — `fn_worker_cancel()`,
   запрещена только для очистки МГМ.
5. **Таймауты**: 300 мс на команду, 10 с дедлайн чтения, 30 с — очистка МГМ;
   повтор команды допускается только в пределах дедлайна и только для чтения.
6. **UI**: собственные view + встроенный u8g2-шрифт с кириллицей; блоки
   информации — секции с заголовком и строками; анимация `A_FNLooking`
   сохраняется и живёт в `fn_view_wait` на всех экранах ожидания.
7. **Безопасность**: очистка МГМ блокируется, если ФН не определён как МГМ;
   подтверждение обязательно; во время ожидания Back не прерывает операцию;
   команда не дублируется.
8. **Тесты**: чистое ядро — host-тесты; транспорт/воркер — на устройстве;
   golden-кадры — общий источник истины для обеих платформ.

## Ловушка `*_LE` / `*_BE`: что именно перепутано

Имена в `lib/fn/fn_helpers.c` противоположны фактическому порядку байтов.
Текущий код согласован внутри себя, поэтому «исправление по имени» без правки
`calc_crc16()`/`check_crc()` ломает разбор ответов. Замена выполняется
атомарно на этапе R1.

| Старое имя | Что реально делает | Замена |
|---|---|---|
| `two_uint8t_to_uint16t_LE(b)` | `b[0] << 8 \| b[1]` — **big-endian** значение | удаляется; чтение CRC — `fn_wire_u16le_get()` после исправления `calc_crc16()` (значение CRC становится числом, в кадре — LE) |
| `two_uint8t_to_uint16t_BE(b)` | `b[1] << 8 \| b[0]` — **little-endian** значение | `fn_wire_u16le_get()` |
| `uint16t_LE_to_uint8t_bytes(v)` | `[v >> 8, v]` — **BE** на проводе | `fn_wire_u16le_put()` (согласованно с исправленным CRC) |
| `uint16t_BE_to_uint8t_bytes(v)` | `[v, v >> 8]` — **LE** на проводе | `fn_wire_u16le_put()` |
| `calc_crc16(data, start, end)` | считает CRC и **переставляет байты** в возвращаемом значении; внутри `end = end - 1` | `fn_wire_crc16_ccitt(data, len)` — число без перестановки, длина вместо «последнего индекса» |
| `check_crc()` | сравнивает с уже переставленным значением | `fn_wire_crc16_ccitt()` + `fn_wire_u16le_get()` в конце кадра |

Правило: после R1 в проекте нет ни одной функции с `LE`/`BE` в имени, кроме
`fn_wire_u16le_*`; порядок байтов задаётся именем функции, а не комментарием.
История, таблица и запрет «чинить по имени» фиксируются в
`docs/byte-order.md` (создаётся в R1, дополняется в R8) и дублируются в
`AGENTS.md`.

## Risk Register

| Риск | Влияние | Смягчение |
|---|---|---|
| «Большой взрыв» при переписывании ломает рабочий обмен | Высокое | Поэтапность R0–R8, golden-кадры, зелёные тесты после каждого этапа |
| Переименование байтовых helper'ов без правки CRC ломает парсинг | Высокое | R1 выполняется атомарно: слой + `calc_crc16`/`check_crc` + все вызовы + тесты в одном изменении |
| Шрифт с кириллицей съедает RAM (FAP грузится в RAM) | Среднее | Компактный subset (кириллица+латиница+цифры+пунктуация), бюджет ≤6 КБ, замер `free` |
| UTF-8-литералы не совпадают с таблицей глифов шрифта | Среднее | Шрифт с Unicode-таблицей, контрольная строка алфавита на экране в R6 |
| Смена приоритета UART-потока влияет на приём | Среднее | Проверка на реальном ФН, повторяемость 20 обменов, отсутствие потерь байт |
| Неполные/короткие ответы ФН вызывают чтение за границей | Высокое | Парсеры bounds-safe, тесты на усечённые буферы, host-fuzz кодека |
| Изменяющая команда уходит на боевой ФН | Критическое | Preflight по `30h`/`33h`, подтверждение, тест «боевой ФН → команда не отправлена» |
| Расширение scope (36h–39h, Архив ФН, маркировка) | Среднее | Вне scope: только команды, требуемые спекой (30h, 3Ah, 33h, 32h, 3Bh, 3Dh, 10h, 60h) |

## Out of Scope

- Команды `31h`, `35h`, `3Fh`, `36h`–`39h`, `40h`–`47h`, `50h`, `B*h` — не
  реализуются (см. `docs/protocol.md`).
- Фискальные операции (регистрация, смена, чеки), чтение Архива ФН.
- Поддержка I2C-подключения ФН.
- Хранение истории операций на SD.
