# Quickstart: сборка, тесты и приёмка

**Feature**: `001-fn-tester-ux`
**Цель**: воспроизводимо проверить, что рефакторинг не изменил обмен с ФН,
UI соответствует спеке, а память не утекла.

Все команды выполняются из корня репозитория
`/Users/igordanilov/CLionProjects/flipper/flipper-zero_fn_tester`.

## 1. Предварительные требования

| Что | Проверка |
|---|---|
| `ufbt` и SDK | `ufbt --version`; SDK в `~/.ufbt/current` |
| Flipper Zero по USB | `python3 .test_scripts/await_flipper.py <name>` |
| `pyserial` | `python3 -m pip install --user --break-system-packages pyserial` |
| Компилятор для host-тестов | `cc --version` (Apple clang) |
| Реальный ФН / МГМ | для сценариев US1–US4 и очистки МГМ |
| Jira/Confluence | не требуются |

## 2. Сборка

```bash
ufbt                 # release-сборка → dist/fn_test.fap
ufbt lint            # статический анализ
ufbt format          # форматирование (перед коммитом)
ufbt cdb             # compile_commands.json для CLion/clangd
```

Ожидание: сборка без warning-ов, `dist/fn_test.fap` создан, версия `0.6`.

## 3. Host-тесты (быстрый цикл, без устройства)

```bash
make -C tests/host            # сборка и прогон
make -C tests/host check-layers
make -C tests/host asan       # host-тесты под AddressSanitizer
```

Ожидание: `OK` по всем наборам, ненулевой код возврата при любом падении.
Покрываются: байтовый слой, кадр, golden-кадры, парсеры, каталог ошибок,
границы буферов, правила слоёв.

## 4. Тесты на устройстве

```bash
# тестовый профиль: юнит-тесты + CLI-команда fn_test, консоль VCP остаётся
FN_TESTS=1 ufbt launch FLIP_PORT=/dev/cu.usbmodemflip_<NAME>1

python3 .test_scripts/units.py <NAME>              # все наборы
python3 .test_scripts/units.py <NAME> fn_wire      # один набор
python3 .test_scripts/units.py <NAME> fn_worker
```

Ожидание в отчёте:

```text
Failed tests: 0
Consumed: ... ms
Leaked: ...
Status: PASSED
```

Допустимо: `[SKIP]` для тестов, которым нужен реальный ФН (ФН не подключён).
Недопустимо: рост `Leaked` между прогонами, `Status: FAILED`.

## 5. Проверка исправления `*_LE`/`*_BE` (ключевой сценарий)

1. `make -C tests/host` — тесты `test_wire`, `test_frame`, `test_parsers`
   должны подтвердить:
   - `fn_wire_u16le_get({0x68, 0x01}) == 0x0168`;
   - `fn_wire_crc16_ccitt()` для кадра `04 01 00 30` (по `01 00 30`) даёт
     `0xCDFF`, запись LE — `FF CD`;
   - запрос `30h` собирается в `04 01 00 30 FF CD` побайтово;
   - ответ `3Bh` `04 03 00 00 68 01 7C 6D` парсится как 360 дней;
   - `3Dh` 8 байт → `has_marking = false`, 9 байт → 7 %.
2. `FN_TESTS=1 ufbt launch` + `units.py <NAME> fn_wire` / `fn_frame` / `fn_parsers`
   — те же значения на устройстве.
3. На реальном ФН: «Информация об ФН» и «Фаза жизни» показывают корректные
   SN, ФФД, дату, № ФД, дни и ресурс (сверить с эталоном/другим тестером).

Если хотя бы один пункт расходится — откатить R1 целиком (не «чинить» имена
точечно).

## 6. Ручная приёмка (US1–US5)

Подключение: модуль расширения или провода по распиновке; ФН запитан.

| # | Действие | Ожидание |
|---|---|---|
| 1 | Запустить приложение | Главное меню с 5 русскими пунктами, выбран первый |
| 2 | «Информация об ФН» | Сначала экран ожидания **с анимацией** и текстом «Поиск ФН…», затем данные: SN, этап, смена, документ для ОФД, ФФД, ПО, МГМ/боевой |
| 3 | Прокрутить вниз/вверх | Все блоки доступны, заголовки не оторваны от строк, значения не обрезаны |
| 4 | Back на экране информации | Сразу в меню, приложение работает |
| 5 | «Фаза жизни» | Срок, регистрации, дни, ресурс 5-лет/30-дневный; при маркировке — процент |
| 6 | Back во время ожидания чтения | Не более 1 с до меню, анимация остановлена |
| 7 | Повторить чтение с исправным ФН | Операция успешна без перезапуска приложения |
| 8 | Отключить ФН и выбрать чтение | Через ≤10 с — «ФН не отвечает», Back → меню |
| 9 | «Очистка МГМ» на боевом ФН | «Очистка недоступна: ФН не является МГМ», команда не отправлена, Back → меню |
| 10 | «Очистка МГМ» на МГМ | Предупреждение о необратимости и подтверждение; отказ → меню, ФН не изменён |
| 11 | Подтвердить очистку | Экран «Очистка МГМ…» с подсказкой «до 30 секунд»; Back игнорируется; затем результат |
| 12 | «Распиновка», «О приложении» | Открываются без ФН, русский текст, Back → меню |
| 13 | 10 раз: чтение → Back | Каждый раз ≤1 с; 11-я операция успешна (SC-005) |

Дополнительно (при наличии инструментов): RPC-снимки экранов по
`.opencode/skills/flipper-zero-app-dev/references/rpc-ui-testing.md`; проверить,
что мелкий шрифт читается (не «полоски»), анимация видна на всех экранах
ожидания.

## 7. Память и производительность

```bash
ufbt cli
# в CLI Flipper:
free
top
```

| Проверка | Ожидание |
|---|---|
| `free` до запуска приложения | baseline |
| `free` после выхода | не ниже baseline − 1 КБ (нет утечки) |
| `top` во время работы | стек UART/воркера не в красной зоне |
| Время до данных (US1) | ≤5 с (SC-001) |
| Время отмены (US2/US4) | ≤1 с (SC-003) |
| Отсутствие ответа | ≤10 с чтение, ≤30 с очистка (SC-006) |

## 8. Диагностика

| Симптом | Что смотреть |
|---|---|
| «Не удалось занять порт 13/14» | `log debug` по тегу `FNUartBus`; подключён ли модуль расширения, не занят ли USART |
| «Повреждённый ответ ФН» | `log debug`: дамп `>>`/`<<` кадров, сверить CRC с `frames.md` |
| Данные выглядят сдвинутыми | проверить, что используется `fn_wire_*`/`fn_frame_*`, а не старые helper'ы |
| Текст — «полоски» | не подключён `fn_font` (использован стандартный шрифт) |
| Анимация не идёт | `enter/exit`-callback не вызывает `icon_animation_start/stop` |
| Приложение зависло после Back | `fn_worker_cancel` не вызван или операция не отменяема (`FlashMgm`) |
| Тесты не запускаются | сборка без `FN_TESTS=1` (команда `fn_test` отсутствует — это норма) |

## 9. Откат

Изменения ведутся по этапам R0–R8 (см. `plan.md`). Откат этапа — возврат
соответствующего коммита; R1 (байтовый слой + CRC) откатывается только целиком.
